## 0. 一句话结论

**"0.24 的低 Loss"是假象**：它几乎全部来自模型学会输出恒定的答案后缀"色"和 EOS，而真正需要判别的答案首字（红/绿）的 Loss 停在 `≈0.70`（二分类随机水平 `ln2≈0.693`）。同时，一个明确的工程缺陷让 Router 从未收到语言梯度——底层 STE 代码全部就绪，只是 `NMindLM.forward` 漏传了一个参数。该缺陷已修复并通过回归测试；但**已有权重是在旧代码下训练的，冻结评测结果不变，要真正获得绑定能力必须重新训练**（本轮禁止，已给出最小实验预登记）。

## 1. 为什么训练 Loss 很低？

逐 token 拆解训练集 4 条样本的 CE（见 `V16_LOSS_BREAKDOWN.json`）：

| 答案 | 答案首字（判别 token）CE | "色" CE | EOS CE | 三者平均 |
|---|---|---|---|---|
| 红色 | **0.703** | 0.017 | 0.009 | 0.243 |
| 绿色 | **0.712** | 0.019 | 0.009 | 0.247 |

- 答案共 3 个 token：首字 `红/绿`（唯一需要区分的）、尾字 `色`（恒定）、`EOS`（恒定）。
- 后两个恒定 token 的 CE 已降到 ~0.01，把均值从 0.70 稀释到 0.24。
- **结论：0.24 的 Loss 不代表学会颜色绑定，只代表学会了"答案以『色』结尾并输出 EOS"。** 这与 V1.5 报告"Loss 下降不能证明理解提升"完全一致，本轮给出了逐 token 级证据。

## 2. 为什么自由生成仍主要输出固定颜色？

候选答案条件对数概率（`V16_TEACHER_FORCING_AUDIT.json`）显示，5 组输入（问小明/问小红/交换颜色/交换顺序）的概率几乎完全相同：

| 输入 | P(红色) logprob | P(绿色) logprob | 候选选择 | 自由生成 |
|---|---|---|---|---|
| 问小红（事实：小明红/小红绿） | **-0.360** | -0.366 | 红色 | "红色" |
| 问小明（同上事实） | **-0.360** | -0.366 | 红色 | "红色" |
| 交换颜色后问小明 | **-0.359** | -0.367 | 红色 | "红色" |
| 交换颜色后问小红 | **-0.359** | -0.367 | 红色 | "红色" |
| 交换陈述顺序问小红 | **-0.361** | -0.366 | 红色 | "红色" |

- 红色概率在所有情况下都略高于绿色（约 0.005 的对数概率差），因此贪婪解码恒定输出"红色"。
- 训练数据是平衡的（红 2 : 绿 2），固定红色/固定绿色的基线准确率都只有 50%——**固定红色是模型自己学到的偏置，不是数据偏斜导致的**。
- Teacher-forced 的 gold 答案概率与候选评分数值一致，说明**评分/解码口径本身没有错**，问题在模型输出分布对问题不敏感。

## 3. 模型是否真正利用被询问实体？

**没有。** 证据：

- 问"小明"vs 问"小红"，同一事实下：
  - 最终 logits 余弦相似度 `0.999999`，L2 差 `0.134`
  - `h.mean()` 余弦相似度 `0.999995`，L2 差 `0.016`（`V16_ENTITY_BINDING_PROBE.json`）
- N-Cell 状态轨迹最后一步，两种问题的 top-3 完全相同：`[298(红), 326(绿), 4078]`
- 冻结表示的线性探针（只检查可解码性，不计入能力分）准确率 `50%`——隐藏状态里连"问谁→什么颜色"的线性区分信息都没有。

实体信息在输入后确实改变了中间状态（V1.5 已确认），但**没有转化为对答案 token 概率的有意义区分**。

## 4. 问题发生在哪一层？

按证据强弱排序：

1. **【已证明·工程缺陷】Router 梯度断路**：`NMindLM.forward` 调用 `blocks.forward_sparse(z, h, w, route.indices)` 时漏传 `weights=route.weights`。而 `NCell.forward_sparse` 明确实现了 STE 梯度路径，`BlockRouter.route` 也返回带梯度的 `weights`——基础设施齐全，唯独调用处没接线。实测 `router.score_mlp.*` 梯度全为 `None`（`V16_FIX_VALIDATION.json`）。这解释了历史报告反复出现的"Router 语言梯度仍为 0"。**属于训练信号层，不是架构数学错误。**
2. **【已证明·学习机制】判别信号弱 + 样本极少**：唯一需要判别的首字 Loss 停在随机水平；训练仅 4 条样本、1 种问题模板。模型没有足够信号/样本学会"被询问实体→属性"映射。
3. **【已证明·读出层】读出对实体不敏感**：修复前的 h_mean 读出使两种问题产生近乎相同的 logits。
4. **【未区分的假设】**：即使 Router 恢复梯度，仅靠 4 样本 + 256 步是否足以学会绑定，无法从冻结诊断判定——需下一轮训练实验（见第 8、9 节）。**不编造因果结论。**
