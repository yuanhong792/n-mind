## 一、P0：UTF-8 修复（唯一确凿的正结果）

**根因**：旧 decoder 对每步 argmax token 不检查字节合法性。V1.6 模型在封存题上输出非法起始字节（`0xa3`、`0x82`），最后一次性 decode 才报 `byte_decode_error`。

**修复**：
- `tokenizer_v2.py` 新增 `token_bytes()`：单 token → 原始字节
- `bpe_decoder.py` 新增 `utf8_prefix_status()`：严格 RFC 3629 状态机（complete/incomplete/invalid，含 overlong/surrogate/越界检查）
- `generate_bpe(utf8_safe=True)`：逐候选展开字节、拒绝破坏 UTF-8 的 token、允许汉字字节跨 token、UTF-8 未完成时禁止 EOS；原始 token 与被拒候选全部留档
- 单元测试 11/11（状态机）+ 3 项 pytest 通过

**冻结 V1.6 模型 A/B 对比**（`V17_DECODER_FIX.json`，权重完全未变）：UTF-8 合法生成 **1/4 → 3/4**。此收益**仅来自 decoder**，不代表模型学到新知识。

**剩余 1/4 为何仍失败**：decoder 只能拒绝非法字节后选次优 token；模型 logits 本身在这些题上把非法字节排第一，过滤后仍无法生成正确中文。这是**模型能力问题，不是编码问题**——两类原因已分离。

## 六、五个必答问题（诚实回答）

**1. N-MIND 现在能够自主生成什么中文内容？**
能稳定生成 5 种中文颜色词（绿色/红色等）与"你好，<名字>"式问候（36 组中 35 组输出合法中文、EOS 结束、UTF-8 100% 合法）。但这些输出与输入语义基本无关，不构成有意义的对话。

**2. 它是否学会了根据不同人物查找对应属性？**
**没有。** 未见实体绑定准确率 12%（8 色随机水平 12.5%），低于最近属性（48%）与位置（52%）基线；36 组实测中问任何人/物品都答"绿色"。

**3. 它是否学会了简单上下文关联？**
**部分迹象但不成立。** 多轮第 1 轮"我叫李红"能得到"你好，李红"，但紧接着问"我叫什么？"输出空串 + EOS。E_context 封存集仅 1 条，**统计不充分，判定 INCONCLUSIVE**。

**4. 它是否在未见组合上超过固定答案和位置捷径基线？**
**没有。** B_bind 0.12 < 固定答案基线 0.103 附近且远低于位置捷径 0.517；反事实成对 0/1。模型本身收敛到"固定输出绿色"，Constant Answer 基线才是它当前策略。

**5. 距离基础中文自由对话还缺少哪些具体能力？**
① 输入语义解析（当前对"你好"也答颜色）；② 实体—属性键值绑定（B/C 任务全失败）；③ 多轮状态保持与读取（第二轮就崩）；④ 非颜色域回答能力（只会颜色词）；⑤ 答案与问题的语义一致性（固定输出退化）。这些不是调步数能解决的——1536 步 × 6000 样本已证明。

## 七、根因指向（诚实：仍未唯一确定）

V1.6 已证伪"Router 梯度缺失"。V1.7 在扩大数据 1500 倍、加权判别 token、1536 步后仍失败，进一步收窄假设：

| 假设 | 证据 | 下一步验证（不预设结论） |
|---|---|---|
| H1 读出层信息瓶颈：`h.mean(dim=1)` 抹平实体位置 | V1.6/V1.7 冻结探针均 50%；训练后状态仍不可分 | 冻结参数：用完整 h 序列（非 mean）训练线性探针解码答案；若仍随机则确认读出丢失 |
| H2 架构容量/机制不足以做符号绑定 | 2 blocks×32 hidden；Query-Attention、Router 梯度先后证伪 | 最小机制实验：在冻结表示上测键值绑定线性可分性；不可分才考虑改读出/容量 |
| H3 答案监督信号被 EOS 退化主导 | 自由生成多为直接 EOS；加权后仍退化 | 单独实验：EOS 权重设 0/极低，禁止第一步 EOS，观察是否被迫学习内容 |
| H4 训练/推理 token 口径或状态传递缺陷 | 封存 UTF-8 已排除编码；但生成仍固定 | 逐 token 对比训练 target 与推理 logits 分布，确认无泄漏/错位 |

**明确不做的**：不再盲目加步数（已 1536 步证明无效）；不改封存集；不为降 Loss 调验收标准。下一步须选定一个机制变量，重新预登记并授权。
