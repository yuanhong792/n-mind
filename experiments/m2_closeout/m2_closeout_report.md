## 3. pred×稀疏 机制诊断（M2.2）

事实（gradient_diagnostics.json，已训练 checkpoint 上逐损失 autograd.grad）：

1. **稀疏模式下路由器是任务盲的**：action/pred/probe 对 router 的梯度全部为 0，
   只有 balance/entropy 正则训练 router。稠密对照 B 的 router 拿到任务梯度
   （pred_share 0.0036），且其上 action×pred cosine = **-0.453**（冲突证据），
   但 B 仍收敛到 0.95+——冲突存在 ≠ 失败原因。
2. **D 的失败是'从未收敛'不是'先学会再崩'**：训练轨迹（fix.json val_occ_trace）
   显示 D 的 action loss 卡在 0.63-0.75、val_occ 爬到 ~0.58 停滞；F1 稳步到 0.87，
   B 直接到 0.94。
3. pred 目标侧梯度（D 特有通路）在已训练 D 上对 blocks 的范数占比仅 ~0.0005，
   blocks 上 action×pred cosine -0.143（F1 为 -0.028）——**方向冲突信号存在但量级小**，
   单凭它解释 40 个百分点的差距证据不足。
4. 探针损失是 encoder 的主要训练者之一（grad 范数 > action），I_no_probe 掉到
   0.62 与此一致。

**已证实**：detach_pred_target 把 pred 梯度限制在 predictor/encoder 输入路径，
且 D→F1 提升 32.6pp 在 4 个 seed 上复现。**尚属假设**：'pred×稀疏的具体梯度冲突
机制'——已记录的只是相关与通路存在性，机制级证明需要训练轨迹干预实验（未做）。
候选修复（本轮新增）：F10 给稀疏路由接上 STE 任务梯度（tests/test_router_ste.py
钉死'前向不变+router 有梯度'），结果见第 4 节。

## 6. M2 验收判定

| 门槛（提示词 C/M2.5） | 状态 |
|---|---|
| 1. 工件登记完整 + 全部 checkpoint 重载评分 | ✅ 22/22 |
| 2. 数据审计 + 冻结 holdout + 独立 CPU 基准可复现 | ✅（基准已完成） |
| 3. ≥3 新 seed 的 C/D/F1/F7 齐全 + 不确定性 | ✅（另含 A/B） |
| 4. F7 或更优稀疏候选相对 C 差距 ≤3pp、pred/probe 不退化 | 🔶 F10 均值 0.914，距 C 2.7pp（n=5）——均值达标但方差大，待定案 |
| 5. 原 32 项测试 + 新增回归测试全过 | ✅ 当前套件 49 项 |

**判定：M2 CONDITIONAL（未闭环，距闭环一步）。** 稀疏架构本身稳定（C 多 seed
0.941±0.002）；失败机制定位到'稀疏路由任务盲 + pred 训练路径'的相互作用，
新增修复候选 F10（STE 路由）均值口径首次达标（0.914，距 C 2.7pp，n=5）但方差大；
F9 证实软化正则单独无效、detach 必要。判定 CONDITIONAL 而非 ACCEPTED 的原因：
F10 种子间 std 0.031（最差 0.877），且 pred 分支有效性只验证了'未常数化'
（z_std/z_hat_std 同量级），未验证显式的下一状态预测准确率（M2.2 要求项）。
M2 冻结基线（供 M3 引用）：C_sparse_ce 0.941±0.002 / F1_detach 0.895±0.016 /
F10_ste 0.914±0.031（均 CPU、480 步、v2-disjoint-pairs split）。
