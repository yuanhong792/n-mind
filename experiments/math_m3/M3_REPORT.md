# N-MIND M3 最终报告 — Minimum Sufficient Neural Computation

分支：`experiment/minimum-sufficient-computation-m3`（基于 M2 提交 `23c7d09`）
状态：**TRAINED（真实梯度训练已完成）** — 2026-11-24 执行

> **最高研发纪律**：不将更小参数量直接等同更低计算成本；不将更低训练 Loss 直接等同更强智能能力；
> 不将门控值接近 0 直接等同实际节省计算；能力低于参考模型时不通过参数量或运行时间宣称同等能力效率突破。

## 1. 执行摘要（真实训练结果）

本轮完成 M3 全部交付物，包括 **4096/4096 optimizer.step 真实训练（261.44s / 预算 3600s）**、
四架构双种子公平对照、统一评测、ISO 能力成本、Pareto、训练后动态路由与 48 组真实生成样例。

**决定性结论：本轮假设未获支持。**
- 固定验证面板双 seed 宏均值：**R2 Transformer 0.5063** > M3-B 自适应 0.2619 > R1 GRU 0.1255 > M3-A 低秩 0.0931。
- 两个新架构（M3-A/M3-B）**连 30% ISO 门槛都未达到**；只有 R2 稳定达到 30%/40%/50%。
- 因此 **不能宣称任何"同等能力下计算更少"的效率收益**，所有效率比较标记 `NOT_COMPARABLE_OR_TARGET_NOT_REACHED`。
- M3-A 每 token MAC 仅为 R1 的 30.4%，但能力低于 R1（0.0931 vs 0.1255）——**这是"更低计算 ≠ 同等能力"的直接反例**。
- M3-B 硬门训练后实际跳过 **82.55%** 稠密计算，但准确率从软门 0.3333 降到 **0.2157（-11.76pp）**；
  按纪律以硬门为准，**软门成绩不得替代**。
- 唯一明确正面结果：R2 反事实成对正确率 **0.75/400**，M3-B 为 **0.5525/400**；但查询切换四架构全为 0。

**授权与纪律**：P13 要求用户明确授权；本次依据用户"继续完成没有完成的任务"指令启动训练，
未继承 M2 授权。权重 16 个 checkpoint 仅本地保存，未上传公开仓库。Stable 始终只读。

## 4. 真实训练结果（四架构 × 2 seed × 512 步）

统一配置：AdamW lr=3e-3、weight_decay=1e-4、BS=32、clip_grad=5.0、每 64 步评测、SEP 协议、
随机初始化（不使用任何预训练权重）、相同样本与预生成 batch 顺序。

| 架构 | 参数量 | seed1 best | seed2 best | 双 seed 宏均值 | 代表 checkpoint |
|---|---:|---:|---:|---:|---|
| R1 GRU 参考 | 110694 | 0.1192 | 0.1317 | **0.12545** | s2_best |
| R2 微型 Transformer | 79718 | 0.5083 | 0.5043 | **0.50630** | s1_best |
| M3-A 低秩 | 41478 | 0.0912 | 0.0950 | **0.09310** | s2_best |
| M3-B 自适应 | 69897 | 0.2407 | 0.2831 | **0.26190** | s2_best |

**架构间比较结论**：R2 显著领先所有候选；M3-B 约为 R2 的一半；M3-A 甚至低于 GRU 参考。

## 6. ISO 能力成本与 Pareto（真实）

稳定达标规则：连续 2 个测量点 macro ≥ target（末尾点达标亦接受）；两 seed 按 local_step 对齐取均值。

| 架构 | 30% | 40% | 50% | ≥60% |
|---|---|---|---|---|
| R1 GRU | TARGET_NOT_REACHED | — | — | — |
| R2 Transformer | 192 步 / 54.66G MAC | 256 步 / 72.88G MAC | 512 步 / 145.76G MAC | — |
| M3-A 低秩 | TARGET_NOT_REACHED | — | — | — |
| M3-B 自适应 | TARGET_NOT_REACHED | — | — | — |

**只有一个模型达到 30% 以上**，因此不存在"双方在同一任务达到约定能力"的比较前提。
`M3_PARETO_RESULTS.json` 中 `efficiency_vs_R1` 三项全部为
`NOT_COMPARABLE_OR_TARGET_NOT_REACHED`；**E1–E5 效率等级本轮一律不授予**。

Pareto 非支配集合为四个架构全部入选，原因是各架构在不同资源维度各有极小值
（M3-A 状态元素 96、R2 延迟 0.001693s、M3-A 每 token MAC 31392 等）。
**这不表示四个架构同等优秀**：M3-A 能力低于 R1，其"非支配"仅来自更小的状态与更低的 MAC。
未达 30% 门槛者的 `cost_train = null`，Pareto 计算按 +inf 处理，不使用全量训练 MAC 冒充达标成本。

## 7. 训练后动态路由（P4.4）

加载 `M3-B_adaptive_computation_s2_best.pt`，在同一样本上比较软门/硬门：

- 硬门实际跳过 **82.55%** 稠密 MAC；路径利用率 C0=0.78%、C1=86.33%、C2=12.89%。
- 控制器自身成本 147456 MAC，已单独计入，未隐藏在路径成本中。
- 软门（稠密）准确率 **0.3333**，硬门（稀疏）准确率 **0.2157**，差 **-11.76pp**（51 条，每任务前 3 条）。
- 按预注册纪律：**以硬门成绩为准**，软门仅作对照，不得用软门成绩宣称稀疏推理无损失。

结论：硬门确实"跳过了计算"，但**以可测量的准确率下降为代价**，且训练后路径分布高度偏向 C1，
并非随机均匀（对比未训练时 C0/C1/C2 ≈ 32%/34.8%/33.2%）。这是真实现象，不是理论推测。

## 9. 验证方法与证据链

**顶尖专家会额外做而我已纳入的工作**：预注册方案在训练前固定并禁止事后改口径；
四架构同样本同 batch 顺序双种子；封存集绝不参与选模；checkpoint 逐张量回读 + 文件 SHA256；
反事实配对与查询切换分离；长度/格式外推；每 64 步学习曲线；软门/硬门分别报告；
未达门槛不外推成本；能耗标注不可用；权重不上传；失败案例原样保留。

**依赖的原始数据**：`data/m3_{train,val,sealed,counterfactual,generalization}.jsonl`、
`M3Tokenizer`（SHA `511b2a9e...`）、`M3_BUDGET_LEDGER.jsonl`（4096 step 事件）、
16 个 checkpoint 的 `meta`（初始化 SHA、数据 SHA、tokenizer SHA、代码版本、公式版本）、
`M3_COMPUTE_ACCOUNTING.json` 的实测延迟与解析 MAC。

**工具与方法**：系统 Python 3.12.10 + torch 2.10.0+cpu（20 线程）；AdamW + 梯度裁剪；
SEP 协议自回归贪心生成（禁止 PAD/SEP，自然 EOS）；固定面板宏/微准确率；
ISO 稳定达标成本；Pareto 非支配排序；真 KV Cache 等价性验证；反事实成对评测；
逐样本软/硬门对照；预算台账跨重启累加。

**独立验证途径**：① 双 seed 方向一致性；② 封存集（294 条）独立复核面板结论；
③ 反事实 400 对与查询切换分离；④ 泛化集外推；⑤ 训练后 checkpoint 重测路由；
⑥ M2.1 交叉协议复现 SEP 提升；⑦ KV Cache 与全前向 1e-6 等价；⑧ 20 项数学验证；
⑨ checkpoint 逐张量回读与 SHA256；⑩ 与 R1/R2 参考模型同面板对照。

**无法验证 / 缺失证据（明确说明，不自行补全）**：
1. **能耗**：无硬件功耗计，`M3_COMPUTE_ACCOUNTING.json` 中能耗为 NOT_AVAILABLE，禁止 TDP×时间伪造。
2. **同等能力计算效率**：除 R2 外无模型达 30% 门槛，比较前提不成立；E1–E5 不授予。
3. **长距离（16/32/64）能力**：sealed 集只含距离 4/8，未测更长距离。
4. **正交保护记忆进主模型**：`NOT_RUN`，投影成本 3072 MAC，未证明收益。
5. **自然语言的广泛泛化**：本实验仅在 MiniLang 合成任务集上验证，不能外推到通用语言任务。
6. **统计显著性**：双 seed 为小样本，未做多随机种子的置信区间；架构排序为观察值而非显著性结论。
7. **M3-A 训练不稳定原因**：观察到 384 步后 macro 下降，但未做梯度/坍缩诊断，原因未知。

## 10. 最终问题回答（22 问）

1. **SEP 提升在正确协议下是否仍成立？** 是，legacy→legacy 0.0836 vs sep→sep 0.4511（+0.3675）。
2. **历史监督冲突有多少？** 真实受监督位置 128 前缀 / 299 位置（0.23%），原报 1663 为虚高。
3. **主要计算成本来源？** 解析为 GRUCell/head、注意力/FFN、低秩+对角+读出；实测 R1 的 Python 逐 token 循环占 44.77%。
4. **Transformer 为何在 M2/M3 领先？** 注意力对序列依赖建模强；本轮 R2 在 192 步即达 0.449，双记忆/低秩在 512 步内未追上。原因未被单变量消融证实，属观察性解释。
5. **低秩状态更新是否保持相同能力？** 否。M3-A 面板 0.0931 < R1 0.1255，未保持能力。
6. **哪个低秩维度最具计算效率？** 未验证。本轮只跑 r=16；4/8/16/32 的 Pareto 未做，不能回答。
7. **最小神经状态需要多少元素？** 有效秩代理显示 dim=128 时有效秩 30，但本轮 M3-A 用 96 状态元素仍能力最差；最小充分维度 **未确定**。
8. **自适应计算是否真正跳过昂贵运算？** 是，训练后硬门跳过 82.55% MAC；但准确率下降 11.76pp。
9. **计算决策自身消耗多少资源？** 控制器 `Linear(2d,3)`，每 token 2×d×3 MAC；本轮实测控制器 147456 MAC 并单独计入。
10. **新公式是否减少实际 CPU 时间？** 无梯度基准中 M3-A/M3-B 前向延迟低于 R1，但**同等能力下**的 CPU 时间未验证，不宣称收益。
11. **哪些公式有数值稳定性问题？** 正交投影分母趋零需安全退化（已实现）；极端输入测试 PASS；未发现发散。
12. **正交保护记忆是否值得继续？** 未决定。`NOT_RUN`，投影成本 3072 MAC，待独立实验证明收益。
13. **新架构是否减少训练样本需求？** 否。在 512 步内两候选均未达标，而 R2 在 192 步达 30%。
14. **达到相同能力需要多少累计计算量？** 只有 R2 有 ISO 数据（30%/40%/50% = 54.66G/72.88G/145.76G MAC）；其他模型未达 30%，不外推。
15. **是否超过 GRU 计算效率？** 否。M3-A/M3-B 能力均低于 R1，不得宣称效率超过。
16. **是否超过微型 Transformer 计算效率？** 否。R2 0.5063 远高于两候选。
17. **是否达到 E1 或更高效率等级？** 否，不授予。比较前提不成立。
18. **哪些数学机制有研究基础？** 低秩状态更新、对角动力学、正交投影保护、信息瓶颈代理、KV Cache，见 `M3_RESEARCH_SOURCES.md`。
19. **哪些公式属于本项目新假设？** 对角+低秩+门控复合更新、三路径神经控制器、正交保护安全退化实现；为组合假设，不宣称原创发明。
20. **哪些方向保留/淘汰/继续？** 保留 SEP、KV Cache、M2.1 修复；继续验证自适应硬门的准确率-成本权衡与 query readout；暂不进主模型正交保护；本轮无明确"淘汰"技术，但低秩 r=16 配置在本任务上表现不佳。
21. **反事实能力如何？** R2 300/400、M3-B 221/400、R1/M3-A 0/400；查询切换四架构均接近 0，事实绑定有初步证据但不普适。
22. **本轮是否发现"最小充分神经计算"？** 没有。低 MAC 架构未同时保持能力；最小充分状态与可比效率仍未验证。这是失败的假设检验，不是成功的效率突破。

## 11. 五类收益的严格区分

| 收益类型 | 本轮状态 |
|---|---|
| 理论收益 | 低秩 O(d²)→O(dr) 复杂度分析成立；有效秩远小于维度 |
| 算子实测收益 | 20/20 数学验证 PASS；KV Cache 等价 1e-6；正交投影性质验证 |
